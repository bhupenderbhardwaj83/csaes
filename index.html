🔤 The Master's Blueprint: Basic Syntax at a Glance

Core Building Blocks

Every regular expression in LogScale either filters stream events in-memory, or extracts values into dynamic fields. Learn these four core building blocks:

1. Inline Match Filter Fastest
field = /pattern/flags

Filters stream events directly. Append /i for case-insensitivity on Windows process names and command lines:
FileName = /^(?:powershell|pwsh)\.exe$/i

2. Dynamic Extraction Extraction
| regex("pattern", field=Field)

Extracts named capture groups (?<Var>...) into queryable fields for grouping and calculations:
| regex("\.(?<Ext>[^.]+)$", field=TargetFileName)

3. Boundary Anchors Performance
^ (start)  |  $ (end)

Terminates evaluation on byte 1 if unmatched. Always escape literal dots (\.) and Windows slashes (\\):
FilePath = /^C:\\Windows\System32\/i

4. Classes & Groups Surgical
\d, \w, \s, (?:a|b), [^set]

Use (?:...) for alternation without wasting memory on unwanted captures:
CommandLine = /-(?:enc|encoded)\s+[A-Za-z0-9+/=]{20,}/i

⚖️ The Master's Golden Rules: Key Do's & Don'ts

Analyst Discipline

"Apprentice, speed and precision come from discipline. Observe these rules and your queries will never exhaust the cluster:"

✅ The Master's DO's

High Performance
  • 1. Filter by Index Tag First
    Always anchor queries with #event_simpleName before regex. Scope down to millions of events, not billions.
  • 2. Anchor String Boundaries (^ and $)
    Use ^ or $ whenever matching prefixes or file extensions. Fails immediately on byte 1 if unmatched.
  • 3. Append Case-Insensitive Flag (/i)
    Windows process names, paths, and commands are case-insensitive. Always append /i.
  • 4. Use Non-Capturing Groups ((?:...))
    Use (?:a|b) for alternation. Allocates zero capture buffer memory, keeping queries lean.
  • 5. Double Escape Windows Path Backslashes
    A literal backslash requires double escaping: /\\windows\\system32/i.
  • 6. Use Non-Greedy or Negated Quantifiers
    Prefer .*? or [^\s]* over greedy .* to prevent catastrophic backtracking on long command lines.

❌ The Traps to AVOID (DON'Ts)

Fatal Pitfalls
  • 1. Don't Regex Across the Unfiltered Fleet
    Never run unanchored regex without an index tag. It forces full table scans across petabytes of telemetry.
  • 2. Don't Leave Suffixes Unanchored
    Writing /cmd\.exe/ matches mycmd.exe.tmp. Always anchor: /\\cmd\.exe$/i.
  • 3. Don't Use Boolean OR Between Field Filters
    User=/admin/ OR User=/root/ throws syntax errors. Use regex alternation: User=/^(?:admin|root)/i.
  • 4. Don't Use Greedy .* on Large Command Lines
    Writing /powershell.*-enc/i causes engine timeouts on 8,000-character obfuscated Base64 blobs.
  • 5. Don't Leave Literal Dots Unescaped
    Writing /script.ps1/ matches scriptXps1 because unescaped . matches any character.
  • 6. Don't Capture What You Won't Extract
    Don't write (cmd|powershell) when you don't need the variable. Every capture group costs CPU cycles.

Syntax Approaches

Choose the right syntax based on whether you are filtering raw records, extracting new fields, or matching simple substrings:

⚡ The Master Hunting Law: Which Index to Start From & Why

CrowdStrike Falcon Next-Gen SIEM (LogScale engine) processes petabytes of telemetry across millions of endpoints. Fields prefixed with a hash (#) are physical ingest index tags evaluated in block headers on NVMe/S3 tiers. When a query begins with #repo="base_sensor" #event_simpleName="UserLogon", the storage engine performs block skipping—bypassing 99%+ of compressed disk segments without decompressing or parsing them.

⚠️ The Full-Scan Penalty: If you start a query with an unindexed field (e.g., CommandLine=/powershell/i or UserName="admin"), LogScale is forced to decompress every single segment block in the entire cluster across all hosts. Always anchor your hunt with an index tag first!
Universal 5-Stage Query Anchor Pipeline
1. #repo="base_sensor" // Target repo
2. #event_simpleName="ProcessRollup2" // Event
3. | aid="a1b2..." // Host scope
4. | FileName=/powershell\.exe$/i // Filter
5. | groupBy(UserName, count()) // Aggregate

📋 The 7 Logical Stages of Query Execution

Click 'Copy' to Test Snippets

Executing operations out of order is the #1 cause of query timeouts and logical errors. Follow these 7 stages sequentially:

1️⃣ Stage 1: FILTER FIRST (Narrow Dataset) Pre-Pipe Index

Cardinal Rule: Filter early and aggressively. Indexed tags (#event_simpleName, #repo) must be placed before the first pipe to skip 99% of scanned disk data. 

// Fast: Header block index tags placed first
#event_simpleName="ProcessRollup2" ComputerName="MACN-*"
| FileName=/(powershell|pwsh)\.exe$/i
2️⃣ Stage 2: ENRICH (Add External Context) GeoIP & ASN

Inject threat context or geolocation before calculating statistics. Adds country, city, coordinates, or threat intel lookup matches to raw rows. 

#event_simpleName="NetworkConnectIP4"
| !in(field=RemotePort, values=[80, 443])
| ipLocation(RemoteAddressIP4)
| asn(RemoteAddressIP4)
3️⃣ Stage 3: TRANSFORM & MUTATE (Normalize) := Assignment

Create new calculated fields using :=, normalize strings with lower(), handle null values with coalesce(), or extract substrings. 

// Create converted MB size and fallback identity
| FileSizeMB := Size / (1024 * 1024)
| UserAccount := coalesce([UserName, UserSid])
4️⃣ Stage 4: AGGREGATE (Summarize Data) groupBy + Multi-Metric

Collapse thousands of raw rows into summarized metrics. Group by multiple keys and calculate counts, sums, or collect distinct attributes. 

| groupBy([UserName, ComputerName], function=[
    count(as="TotalAttempts"),
    sum(is_failure, as=FailedCount),
    collect(aip)
  ])
5️⃣ Stage 5: POST-PROCESS (Thresholding) Metric Filters

Apply threshold filters to the aggregated metrics computed in Stage 4. Isolate brute-force floods, heavy talkers, or volume spikes. 

// Downstream threshold: only keep high-frequency offenders
| FailedCount >= 5
| TotalAttempts > 50
6️⃣ Stage 6: FORMAT & PROJECT (Display) table() & Time

Select final columns with table(), format timestamps into human-readable strings with formatTime(), and discard raw clutter. 

| _time := formatTime("%Y-%m-%d %H:%M:%S", field=@timestamp)
| table([_time, ComputerName, UserName, FailedCount, TotalAttempts])
7️⃣ Stage 7: SORT & SLICE (Final Ordering) Final Stage

Always sort last. Sorting raw un-aggregated data forces CPU sorting over millions of rows. Sort the aggregated results and apply limit or head(). 

// Surface the top 25 worst offenders
| sort(FailedCount, order=desc, limit=25)

Operators • Semantics • Pitfalls

Avoid syntax errors by mastering the exact semantic difference between comparison, assignment, aliasing, and set membership:

Operator Correct LogScale Syntax Semantic Meaning Fatal Mistake to Avoid
= FileName = "cmd.exe" Comparison filter (matches field value). Using := inside a filter (causes assignment syntax error).
:= FileSizeMB := Size / (1024 * 1024) Assignment / Mutation (creates or mutates a field). Using single = for mathematical calculation or field creation.
as="..." count(as="ExecCount") Alias name for a function output metric. Writing count() := ExecCount or mixing as= with :=.
in() in(field=RemotePort, values=[80, 443, 8080]) Set membership function (checks list values). Writing SQL-style RemotePort IN [...] after a pipe (causes ExpectedExpression error).

Performance & Correctness

🚀 Law 1: Aggregate BEFORE Sorting

10,000x Faster

Sorting after aggregation processes only summary rows instead of millions of raw telemetry events.

// ✅ MASTER ORDER: Counts first, sorts only 500 host records

Query Correctness

After groupBy(), all non-grouped fields vanish from the pipeline unless collected via collect().

📋 The Hunter's Pipeline Construction Checklist

Production Guardrails

Before running or deploying an analytical query, verify these eight guardrails:

  • 1. Filter First
    Scope with #event_simpleName and index tags before any pipe.
  • 2. Transform Early
    Normalize strings (lower()) and regex extraction before grouping.
  • 3. Aggregate to Condense
    Use groupBy() or timechart() to collapse events into summary groups.
  • 4. Thresholds After Grouping
    Write count filters (e.g. failures >= 5) immediately after groupBy().
  • 5. Sort Near the End
    Sort the small aggregated result set, never the raw event stream.
  • 6. Format Last
    Use table() strictly for column layout and alias presentation.
  • 7. Always Specify Limits
    Attach limit=100 on sort() and head() to prevent browser hangs.
  • 8. Collect @id for Alert Rules
    Always include collect([@id]) inside groupBy() for correlation rules.
